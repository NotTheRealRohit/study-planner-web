04The Novelty Proposal04 / 18
Two coupled subsystems that turn time spent into evidence of learning, then route that evidence back into the plan.
PILLAR B · AFTER A SESSION
Assessments
Quiz, written and coding questions generated from the learner’s own material, graded to a mastery signal. Verifies that learning happened.
DURING A SESSION
LLM-Guided Practice
A live, Socratic inline coach that watches the work and nudges. It gives tiered hints, never the finished answer. Supports learning as it happens.
RAG-grounded on the learner’s material Coupled to knowledge-tracing & adaptation Backed by working prototypes Capstone-grade, feature-complete
Standing principle. This is a capstone: build feature-rich and complete, with no MVP shortcuts. The one reversal is the AI/model layer, run on the Google Gemini free tier for a cost-effective, accurate-enough result. Feature scope stays full. Only the models stay cheap.

THE SCORING CONTRACT
Whatever the family, every attempt reduces to score ∈ [0,1] plus a per-skill binary correct (≥ τ ≈ 0.6). That pair is the knowledge-tracing observation, one clean seam into the research pillar.
DIFFICULTY & GRADING
Authored difficulty band 1..5, with a reserved observedDifficulty slot for the adaptive loop. All grading is server-side. No answer keys ever reach the client. Attempts queue offline and grade on reconnect.
Attempts are per-Question, run-grouped: QuestionAttempted → QuestionGraded (1:1 via attemptId). Records local-first. Generation and grading stay online-only.

09Research Coupling: Verified Learning → KT09 / 18
The assessment outcome is not a grade to display. It is the input to a knowledge-tracing model that drives the whole adaptive loop.
01Grading → mastery mapping. The score ∈ [0,1] + per-skill binary becomes a per-concept mastery update, a derived projection cached locally, with a reserved MasteryUpdated event for the loop.
02Knowledge-tracing model. Cold-start-capable tracing (BKT / Deep-IRT family, benchmarked on Eedi & POJ in Phase-1) estimates genuine per-skill mastery from a handful of attempts, the parallel to the Phase-1 pace convergence curve.
03Adaptive difficulty. Mastery selects the next item’s difficulty band. Too easy wastes time, too hard demoralizes. The loop steers toward the productive edge.
04Roadmap feedback. Verified mastery feeds pace calibration and re-projection, and replaces gameable self-reported time. This is the closed loop, and the measured contribution.
Extension narrative vs the base papers: Islam 2024 (predict-then-schedule) and CLST 2024 (cold-start KT). We report mastery calibration (reliability / ECE) alongside AUC. A verification signal must be trustworthy, not just discriminative.

11AI Backend & Cost11 / 18
One JWT-verified Intelligence Service owns every model call, on the free tier, behind a provider abstraction, and hardened against abuse.
Models · Gemini free tier

gen + grade → gemini-3.6-flash
embed → gemini-embedding-001 · 768-dim
Provider abstraction with a local Ollama fallback, vendor-swappable.
Streaming
POST + fetch ReadableStream over /v1/* (header auth, not EventSource), provider-neutral SSE frames. Guide streams deltas. Reveal is a separate gated call.
Prompt architecture
Git-versioned Jinja templates (ported open-notebook), SSTI variable rule, untrusted-content-as-data, native responseSchema.
Abuse hardening
Key server-side only · no endpoint runs a model on arbitrary text (every call bound to a user-owned artifact) · durable Postgres rate-limits · free-tier circuit breaker · audit log.
Cost principle reversed for the model layer only (ticket #14): cost-effective, accurate-enough. Feature scope stays full: full RAG, full KT coupling, all assessment families, live guide.
12Algorithms & Techniques12 / 18
Grounded item generation
RAG retrieval over pgvector → schema-constrained LLM generation, concept-tagged, per family.
Rubric grading (written)
LLM scored against a generated rubric → score ∈ [0,1], per-criterion breakdown.
Sandboxed code grading
Judge0 test-case execution → native verdicts. Hybrid client Pyodide gives instant feedback.
Cold-start knowledge tracing
BKT / Deep-IRT-class model over per-skill observations. Cold-start AUC + ECE calibration.
Adaptive difficulty selection
Mastery-driven next-item band (1..5), steering toward the productive edge.
Tiered Socratic guidance
Line-anchored 4-tier ladder. Structurally gated reveal. Streamed from the service.
Pillar-A engines (Bayesian + shrinkage calibration, CUSUM, GP projection) continue from Phase-1 and now consume the verified-mastery signal. Spaced-repetition re-assessment scheduling starts once the KT loop is sharp.

16Expected Outcomes & Evaluation16 / 18
The deliverable is rigor. We measure each subsystem against an honest baseline and a stated hypothesis.
HEADLINE METRICS
01Generation quality: validity, groundedness & concept-tag accuracy of generated items, plus grader robustness to adversarial submissions.
02KT model: cold-start AUC + full-sequence AUC, mastery calibration (ECE / reliability).
03Guide effectiveness: does tiered guidance help without giving the answer?
04Closed vs open loop: schedule adherence & measured learning gain, verified vs unverified.
THE CENTRAL CLAIM
A plan driven by verified mastery adapts better than one driven by self-reported time. We measure this on adherence and learning gain, against the Phase-1 open-loop system as baseline.
Honest limits. Free-tier data-use is an ethics and limitations note. Scope is a single learner. The real-data closed-loop study is a genuine but small cold-start case. We report it as feasibility, not a benchmark.
